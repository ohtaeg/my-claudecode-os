# 나만의 클로드 OS — 컨퍼런스 학습 추적 OS

> 한 줄 정체성: **한 번에 한 컨퍼런스만 깊게 — "놓친 세션이 흐지부지된다" 한 가지 페인포인트를 푸는 OS.**

---

## 1. 내 업무의 중심 워크플로우는 무엇인가?

**페인포인트**

컨퍼런스 참여 → 듣고 싶은 세션이 많지만 시간 충돌/선착순으로 못 듣는 상황 반복
→ 행사 후 YouTube에 영상이 올라와도 시간·관심이 분산됨
→ **무엇을 놓쳤는지 자체를 잊어버리는** 메타적 단절이 발생
→ 결국 흐지부지되고 못 따라간 채 끝나는 패턴

"흐지부지" 의 핵심은 자료 누적의 부재가 아니라 **진척 추적의 부재** 다. "내가 이 행사에서 뭘 따라잡았고 뭘 놓쳤는가" 자체를 잊는 것.

**워크플로우 두 층 (Phase 1 + Phase 2)**

```
Phase 1 — 행사 단위 진척 관리
   컨퍼런스 페이지 URL(또는 텍스트)
        ↓
   [검증] 정적 HTML 분석 가능? → Yes: 자동 파싱 / No: 텍스트 복붙 폴백
        ↓
   세션 목록을 markdown 테이블로 정리
        ↓
   사용자가 "들음" 마킹 (나머지는 자동으로 "미정/관심")
        ↓
   행사 README.md 에 분류 + 단순 카운트 박제

Phase 2 — 세션 단위 학습 노트
   분류된 세션 중 "관심/미정" 세션의 YouTube URL
        ↓
   yt-dlp 로 영어 자막 자동 추출 (실패 시 사용자 복붙 폴백)
        ↓
   Claude 가 영어 자막 → 한국어 분석·요약
        ↓
   세션 노트 markdown 생성 → 행사 README 행에 노트 링크 자동 연결
```

**OS가 *지금은* 해주지 않는 것**
- 행사 전체 자동 크롤링·우선순위 추천 ("대시보드" 라는 완성형 욕심)
- 슬라이드 PDF·블로그 후기 같은 다른 자료 형태
- 풀텍스트 한국어 번역 ("모든 내용 다 알 필요 없음")

**작업 환경**: macOS / Claude Code CLI / `yt-dlp`

## 2. 나만의 OS에 꼭 포함되어야 하는 핵심 철학·관점은 무엇인가?

**핵심 철학 (한 줄)**
"모든 내용을 다 알 필요는 없다." 풀텍스트가 아니라 **체화된 인사이트** 단위로 학습을 박제한다. 자료가 흩어져 흐지부지되는 것보다, 핵심만 한 곳에 박혀 다음에 찾을 수 있는 것이 낫다.

**행동 원칙 3가지**

**① 점진적 확장 — MVP는 단순하게, 쓰면서 붙여간다**
처음부터 완성형(자동 대시보드, 다중 자료 형태, 멀티 행사 비교 통계)을 만들지 않는다. 작은 가치 단위에서 시작해, 자료가 누적되면 인덱스가 자연 발생하게 둔다. 안 쓰이는 기능은 만들지 않는다.

**② 인터랙션 중심 — 한 줄 입력으로 끝난다**
사용자가 직접 데이터를 정리하지 않는다. URL 한 줄(혹은 텍스트 한 덩어리)을 던지면 추출 → 분석 → 저장이 한 흐름으로 완결된다. 자동 처리가 실패할 때만 폴백을 요청한다.

**③ 풀텍스트가 아니라 인사이트 — 압축이 곧 가치다**
"영어 자막 → 한국어 풀텍스트 번역" 은 만들지 않는다. 분량만 늘고 가치는 안 늘기 때문이다. AI는 영어 자막을 읽고 **발표자가 강조한 통찰**만 한국어로 추려낸다. 단순 사실 나열은 학습 노트가 아니다.

## 3. 내 OS가 일을 잘하려면 어떤 정보(컨텍스트)가 필요한가?

### ① 대상 입력

| Phase | 입력 | 폴백 |
|---|---|---|
| Phase 1 | 컨퍼런스 세션 목록 페이지 URL | 사용자가 페이지 본문 텍스트 복붙 |
| Phase 2 | 개별 세션의 YouTube URL | 사용자가 transcript 텍스트 복붙 |

### ② 어떤 처리 방식으로 자료를 손에 넣을 것인가

**Phase 1 — 단계별 sub-agent 분리 구조 (★)**

`conference-import` 는 얇은 가이드 스킬이고, 실제 처리는 단계별 sub-agent 에 위임한다. 각 단계는 독립 컨텍스트로 실행되며, **실패 시 그 단계만 다시 돌릴 수 있다.**

| 단계 | Sub-agent | 책임 |
|---|---|---|
| 1. 검증 | `conference-validator` | URL/텍스트가 분석 가능한지 휴리스틱 판단. 실패 시 폴백 안내 |
| 2. 추출 | `conference-parser` | HTML/텍스트 → 세션 목록 구조화 |
| 3. 생성 | `conference-mkreadme` | 행사 폴더 + README 생성 |

**검증 휴리스틱 (Step 1):**
`WebFetch` 로 페이지를 받아 정적 HTML 에 세션 데이터가 있는지 패턴으로 판단:

```
받은 HTML 본문에 다음 패턴이 N개 이상 발견되는가:
  - 시간 형식 (10:00, 14:30 등)
  - 세션 제목 후보 (h2/h3/h4)
  - 발표자 이름 패턴
```

- 패턴 3세트 이상 → 정적 HTML, 다음 단계로 진행
- 패턴 거의 없음 → SPA 추정, 사용자에게 "페이지 본문 영역 복붙해주세요" 폴백 안내

> 검증 휴리스틱은 첫 사이트들로 돌려보며 다듬는다. 완벽함이 아니라 "매번 즉흥 판단을 피하는 일관성" 이 목적.

**Sub-agent 정의 위치:** `.claude/agents/conference-{validator,parser,mkreadme}.md`

**Phase 2 — 단계별 sub-agent 분리 구조**

`session-note` 도 동일한 sub-agent 위임 구조. 자막 추출 실패가 잦고 분석 재실행 욕구가 있어 단계 분리 가치가 명확하다.

| 단계 | Sub-agent | 책임 |
|---|---|---|
| 1. 자막 추출 | `session-fetcher` | `yt-dlp` 로 영어 자동 자막(`.vtt`/`.srt`) 다운로드. 봇 차단·자막 없음 시 사용자 복붙 폴백 |
| 2. 분석·요약 | `session-analyzer` | 영어 자막 → 한국어 분석·요약 (중간 풀텍스트 번역본은 생성하지 않음) |
| 3. 저장 | `session-mknote` | 세션 노트 markdown 작성 + 행사 README 의 해당 행에 노트 링크 갱신 |

**Sub-agent 정의 위치:** `.claude/agents/session-{fetcher,analyzer,mknote}.md`

### ③ 어떤 기준으로 분류·요약할 것인가 (★ 철학을 정보로 박는 부분)

**Phase 1 — 분류 마킹 원칙 (노동 최소화)**

| 상태 | 의미 | 마킹 방식 |
|---|---|---|
| **들음** | 행사장에서 들었거나 이미 영상 봤음 | 사용자가 직접 마킹 |
| **관심** | 못 들었지만 따라잡고 싶음 | 사용자가 직접 마킹 |
| **미정** | 아직 결정 안 함 | **기본값** (자동 분류) |
| **스킵** | 명시적으로 안 볼 것 | 사용자가 직접 마킹 (선택) |

→ 사용자는 "들음/관심/스킵" 만 명시적으로 마킹하면 된다. 나머지는 자동 "미정". 50~100개 세션마다 분류 노동이 폭발하지 않음.

**Phase 2 — 세션 노트 큐레이션 기준**

세션 노트는 다음 3개 섹션으로 구성한다. **그 외 정보는 의도적으로 자른다.**

| 섹션 | 내용 | 큐레이션 기준 |
|---|---|---|
| **TL;DR** | 1~3줄 | "이 세션을 한 문장으로 표현하면?" — 주제와 핵심 주장 |
| **핵심 인사이트** | 불릿 3~7개 | 발표자만의 관점 / 실패 경험 / 의사결정 근거. **단순 사실·일반 지식은 제외** |
| **태그** | AWS 서비스·기술 키워드 | 검색·필터링용. 누적되면 행사별 인덱스가 됨 |

**자막 노이즈 정규화**
AWS 기술 용어가 자동 자막에서 깨질 수 있음 (Aurora → 어울러 / Lambda → 남다 등). Claude는 **문맥으로 정규화**해서 표준 명칭을 사용한다.

### ④ 어떤 구조로 박제할 것인가 (영속화)

**디렉토리**
```
artifacts/
└─ conferences/
   └─ aws-summit-2026/         ← 도시 구분 필요하면 aws-summit-seoul-2026
      ├─ README.md              ← Phase 1: 세션 목록 + 분류 + 카운트 (행사 인덱스)
      └─ sessions/
         └─ <세션-슬러그>.md    ← Phase 2: 학습 노트
```

> 현재 `.gitignore` 에 `artifacts/` 라인이 있음. 컨퍼런스 학습 노트는 본인의 자산이므로, **이 OS 본격 가동 시 해당 라인 제거** 해서 깃 추적 대상으로 전환한다.

**행사 README.md 포맷 (Phase 1 산출물)**
```markdown
# AWS Summit Seoul 2026

진척: 들음 12 / 관심 8 / 미정 5 / 스킵 0  (총 25)

| 상태 | 세션 제목 | 발표자 | 트랙 | 노트 |
|---|---|---|---|---|
| 들음 | ... | ... | ... | — |
| 관심 | ... | ... | ... | [노트](sessions/xxx.md) |
| 미정 | ... | ... | ... | — |
```

**세션 노트 포맷 (Phase 2 산출물, frontmatter + 3 섹션)**
```markdown
---
title: 세션 제목
speaker: 발표자
url: https://www.youtube.com/watch?v=...
conference: AWS Summit Seoul 2026
date: 2026-05-XX
tags: [Lambda, DynamoDB, EventBridge]
---

## TL;DR
...

## 핵심 인사이트
- ...

## 태그
- ...
```

### ⑤ 답변 스타일
- 자막의 모든 발화를 옮기지 않는다. 압축이 곧 가치다.
- 발표자가 명시적으로 강조하지 않은 내용은 추측해서 넣지 않는다.
- "전반적으로 다룬다" 같은 모호한 표현 금지. **구체적인 서비스명·결정·경험** 으로 적는다.

## 4. 이 OS에 필요한 스킬

이 OS 의 모든 스킬은 **얇은 가이드** 형태로 짠다. SKILL.md 가 절차를 강요하지 않고 **큰 원칙·판단 기준만** 담고, 분기·예외 처리는 Claude 의 판단에 맡긴다. 외부 인터페이스는 한 줄 입력으로 유지하고, 내부 단계(검증·추출·생성 등)는 SKILL.md 안에서 명확히 분리한다.

| 스킬 | 역할 |
|---|---|
| **`conference-import`** | Phase 1 진입점. 얇은 가이드로 sub-agent 3개(`conference-validator` → `conference-parser` → `conference-mkreadme`)를 순차 위임. 단계별 실패 시 그 단계만 재시도 가능 |
| **`session-note`** | Phase 2 진입점. 얇은 가이드로 sub-agent 3개(`session-fetcher` → `session-analyzer` → `session-mknote`)를 순차 위임. 자막 추출/분석 단계별 재시도 가능 |
| **`session-mark`** | Phase 1 보조. 세션의 분류 상태 변경 (들음/관심/스킵). 사용자가 가장 자주 호출하게 될 메타 스킬 |
| **`session-preview`** | 한 세션의 메타데이터 + 상태 + 노트 TL;DR (있으면) 미리보기. 세션 수 많을 때 특정 세션만 빠르게 점검 |
| **`conference-status`** | 한 행사의 진척 카운트 조회 (예: 들음 12 / 관심 8 / 미정 5). Phase 1 분류 결과를 한 줄로 확인 |
| **`conference`** | 한 행사의 세션 갯수 + 세션 이름 목록 + 각 세션 상태 조회 (예: `/conference aws-summit-seoul-2026`). 세션 수가 많아 한눈에 상태 보기 어려울 때 활용 |

**도입하지 않을 스킬** (정체성 보호)
- 행사 자동 검색·세션 추천 — 행사 사이트마다 구조가 달라 일반화 불가, 자동화 욕심은 결국 깨짐

## 5. 이 OS에 필요한 에이전트

스킬 중 `conference-import` 와 `session-note` 는 단계별 sub-agent 에 위임한다. 각 에이전트는 독립 컨텍스트에서 한 가지 책임만 수행하며, 실패 시 그 단계만 다시 돌릴 수 있다.

**정의 위치:** `.claude/agents/<agent-name>.md`

**Phase 1 (`conference-import` 진입)**

| 에이전트 | 책임 |
|---|---|
| `conference-validator` | URL/텍스트가 분석 가능한지 휴리스틱 판단. 실패 시 폴백 안내 |
| `conference-parser` | HTML/텍스트 → 세션 목록 구조화 |
| `conference-mkreadme` | 행사 폴더 + README 생성 (모든 세션 "미정" 상태) |

**Phase 2 (`session-note` 진입)**

| 에이전트 | 책임 |
|---|---|
| `session-fetcher` | `yt-dlp` 로 영어 자막 다운로드. 실패 시 사용자 복붙 폴백 |
| `session-analyzer` | 영어 자막 → 한국어 분석·요약 (TL;DR / 인사이트 / 태그) |
| `session-mknote` | 세션 노트 markdown 생성 + 행사 README 의 해당 행 갱신 |

**도입하지 않을 에이전트** (정체성 보호)
- Orchestrator 에이전트 — 단계 순서 결정은 진입 스킬의 SKILL.md 가 한다. 별도 메타 에이전트는 과한 추상화
- 단순 유틸 에이전트 (slug 생성·frontmatter 작성 등) — 너무 작은 단위, 분리 가치 없음

## 6. MVP 범위와 자라날 단계

### 🎯 MVP (지금 만들 것)
- Phase 1: `conference-import` + `session-mark` → 행사 README 박제
- Phase 2: `session-note` → 세션 노트 박제
- 조회: `conference-status` (한 행사 진척 카운트) + `conference` (한 행사 세션 목록·상태) + `session-preview` (한 세션 미리보기) + `find-session` (한 행사 안 키워드 검색)
- 첫 행사: AWS Summit Seoul 2026
- 첫 입력 형태: 컨퍼런스 페이지 URL + 세션 YouTube URL

### 🌱 자라날 단계 (실제로 쓰이는 게 보이면 그때 붙임)

> 자라날 단계 = 지금은 안 만들지만 쓰임이 보이면 만들 수도 있는 후보들. MVP만 있으면 답답하고, 자라날 단계만 있으면 점진적 확장이 말뿐이다. 둘이 분리돼야 "지금 만들 것" 과 "나중에 가능한 것" 이 명확해진다.

- 노트 검색 스킬 — 한 행사 안에서 태그/키워드로 세션 노트 찾기 (세션 수가 많을 때 유용)
- `readme-updater` 에이전트 — `session-mark` / `session-mknote` 가 모두 행사 README 의 행을 갱신함. 중복이 실제 문제로 드러나면 공통 에이전트로 분리
- 추가 자료 형태 (슬라이드 PDF, 블로그 후기)
- 본인 관심 키워드 사전 → 큐레이션 가중치
- 실무 액션 아이템·인용 가능한 발언 같은 노트 섹션 추가

### 🚫 의도적으로 만들지 않을 것

> 자라날 단계는 "쓰임이 보이면 만들 수도 있는 것", 이건 "쓰임이 보여도 만들지 않을 것". OS 정체성을 지키는 선이다.

- 행사 전체 세션 자동 크롤링·카탈로그 (사이트마다 SPA 구조로 무너짐 — URL 1개씩 던지는 게 더 안정적)
- 풀텍스트 한국어 번역
- **여러 행사 동시 관리·비교·일괄 처리** (다른 컨퍼런스로의 확장 포함) — 한 번에 한 행사만 깊게 다룬다
- **멀티 행사 통계·태그 추세 분석** — 단일 행사 정체성과 충돌
- **전체 행사 인덱스 조회** — 행사 1개면 의미 없음
- "어떤 일이든 처리할 수 있는 OS" 라는 만능 추상화 — 우리는 한 가지 페인포인트만 깊게 푼다
