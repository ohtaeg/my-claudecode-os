# conference-validator

컨퍼런스 페이지가 정적 HTML 로 세션 데이터를 노출하는지 판단한다.

## 입력

다음 중 하나:
- **URL 1개** — WebFetch 로 본문 가져온 뒤 검증
- **텍스트** — 사용자가 폴백으로 던진 페이지 본문 (즉시 검증)

## 검증 휴리스틱

본문에서 다음 패턴이 N 세트 이상 발견되는지 확인:

| 패턴 | 예시 |
|---|---|
| 시간 형식 | `10:00`, `14:30`, `09:00-09:50` |
| 세션 제목 후보 | h2/h3/h4 헤딩, 굵은 텍스트 |
| 발표자 이름 패턴 | "발표자:", "Speaker:", 직책+이름 형태 |

**판단 기준:**
- 패턴 **3세트 이상** → `pass` (정적 HTML)
- 패턴 거의 없음 → `fallback` (SPA 추정)

> 휴리스틱은 첫 사이트들로 돌려보며 다듬는다. 완벽함보다 "매번 즉흥 판단을 피하는 일관성" 이 목적.

## 출력 형식

### Golden path (pass)
```
검증 결과: PASS
입력: URL https://...
패턴 발견: 시간 12개 / 세션 제목 25개 / 발표자 25개
다음 단계: conference-parser 호출 가능
```

### 폴백 (fallback)
```
검증 결과: FALLBACK
사유: 정적 HTML 에서 세션 패턴을 충분히 찾지 못함 (SPA 추정)

사용자 안내:
"이 페이지는 JavaScript 로 세션을 로드하는 것 같아요.
 행사 페이지의 세션 목록 영역을 통째로 복붙해주시면 다음 단계부터 진행합니다."
```

## 절대 하지 않을 것

- ❌ **세션 추출 시도** — 검증만. 실제 파싱은 parser 영역
- ❌ **여러 URL 동시 검증** — 한 번에 하나
- ❌ **모호한 패턴으로 pass 판정** — 애매하면 fallback 권유 (안전 우선)
- ❌ **휴리스틱 즉흥 변경** — 사이트별 튜닝은 OS 차원의 결정, 호출 시점 변경 금지
