# session-analyzer

영어 자막 → 한국어 인사이트 큐레이션.

## 입력

- fetcher 가 정리한 영어 자막 텍스트
- 세션 메타데이터 (제목·발표자·URL — 출력에 같이 박힘)

## 큐레이션 기준

### TL;DR (1~3줄)
"이 세션을 한 문장으로 표현하면?" — 주제와 핵심 주장. 단순 카테고리 나열 금지.

### 핵심 인사이트 (불릿 3~7개)

**살릴 것:**
- 발표자만의 관점 (자기 경험·견해)
- 실패 경험·시행착오
- 의사결정 근거 (왜 X 를 선택했는지)
- 구체적 수치 / 사례 / 결과

**자를 것:**
- 단순 사실 나열 ("AWS 에는 X 서비스가 있습니다")
- 일반 지식 (교과서적 설명)
- 발표 인트로·아웃트로·자기소개
- "감사합니다" 같은 형식적 표현

### 태그 (5~10개)
기술 키워드·서비스명·도메인. 검색·필터링용. 과잉 금지.

## 자막 노이즈 정규화

자동 자막은 기술 용어를 깨뜨린다. **문맥으로 표준 명칭 복원**:

| 깨짐 예시 | 정규화 |
|---|---|
| 어울러 / 오로러 | Aurora |
| 남다 / 랜다 | Lambda |
| 코기토 / 코그니또 | Cognito |
| 다이나모디비 | DynamoDB |

## 출력 형식

```yaml
title: AWS Bedrock Deep Dive
speaker: 홍길동
url: https://www.youtube.com/watch?v=...
tags: [Bedrock, GenAI, Foundation Models, RAG]

tldr: |
  Bedrock 의 모델 라우팅 전략으로 비용 30% 절감한 사례.
  핵심은 작은 모델 우선 폴백 구조.

insights:
  - "처음엔 GPT-4 급 모델로 모든 요청 처리 → 비용 폭증"
  - "Claude Haiku 우선 → 신뢰도 낮으면 Sonnet → 그래도 낮으면 Opus 폴백"
  - "라우팅 로직은 LangChain RouterChain 으로 구현"
  - "지연 시간은 +120ms 증가했지만 비용 30% 감소가 더 컸음"
```

이 출력이 mknote 단계로 전달됨.

## 폴백·재시도

- **사용자가 결과 미흡 (일반론으로 흐름) 이라고 판단** → analyzer 만 재호출. 새 결과 생성 (mknote 가 덮어쓰기)
- **자막 자체가 정보 부족** → "원본 자막이 분석에 충분치 않습니다" 보고 후 종료

## 절대 하지 않을 것

- ❌ **풀텍스트 한국어 번역** — 분량 늘리지 않는다. 인사이트만
- ❌ **추측해서 인사이트 추가** — 자막에 명시되지 않은 내용 채워넣기 금지
- ❌ **"전반적으로 다룬다" 같은 모호한 표현** — 구체적 서비스명·결정·경험으로
- ❌ **인트로·발표자 인사 인사이트화** — "안녕하세요" 류 자르기
- ❌ **태그 과잉** — 10개 넘기지 않는다. 검색 노이즈
