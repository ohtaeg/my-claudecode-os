# interview

막연한 의도를 Socratic 라운드로 좁혀 결정문(Seed)으로 박제하는 메타 스킬. 단일 책임: **인터뷰 진행 + 트레일·결정 박제**. 실행은 별개 스킬에 위임.

> 참고 베이스: [ouroboros](https://github.com/Q00/ouroboros) 의 #the-loop (Interview → Seed → Execute → Evaluate → Evolve).
> 본 OS 적용: Interview + Seed 만 본체 책임. Execute/Evaluate/Evolve 는 OS 기존 흐름에 위임. 수학 게이트(공식·차원·임계값)는 빼고 **사용자 합의 게이트 + 자가 점검 체크리스트**.

## 입력

- 막연한 의도 1개 (한 문장 또는 한 단락)
- 호출 예:
  ```
  /interview 외부 자막 사이트 활용 어떻게 할지
  /interview 노트 생성 후 상태 자동 전이할지
  /interview 이 스킬 보완하고 싶어
  ```

## 처리 흐름

### Phase 1 — Interview (Socratic 라운드 반복)

각 라운드는 **4블록 형식 강제**:

```
[R<n>] 현재 의도: "<사용자 언어 그대로 인용>"

진단: <어디까지 좁혀졌나, 숨은 가정>

옵션:
  A. <선택지> — 트레이드오프
  B. ...
  C. ...

(필요 시) 정찰·검증: <Bash / WebFetch 등 도구 호출 결과>

선택?
```

라운드가 끝나면 사용자 의도가 한 칸 좁아진다. 다음 라운드는 좁아진 의도를 시작점으로.

#### 진단·옵션 작성 시 던지는 질문 (체크리스트)

매 라운드 **진단** 블록 작성 시 다음 질문으로 **숨은 가정을 노출** 한다. 옵션 카탈로그는 이 질문의 답에서 자연 도출.

1. **이 의도의 숨은 가정은?** — 외부 의존 정도 / 자동화 정도 / 책임 경계 / 사용자 부담
2. **이 의도가 어디서 깨질 수 있나?** — 실패·역효과 시나리오, 외부 변동 영향
3. **본 OS 페인포인트(흐지부지·한 행사 깊게)와 어떻게 닿나?** — 정체성 부합·충돌
4. **이전 회고 거리 / 사례 박제와 닮은 점은?** — `PROJECT.md` 회고 박스, `examples/<slug>/`

질문 결과는 진단 블록에 짧게 녹여 옵션으로 변환한다. 질문 자체를 사용자에게 다 던지지 않음 (내부 가이드).

#### 라운드 종료 자가 점검 (모호함 → 구체성 게이트)

수치 없이 체크리스트 3개. 사용자 확인으로 통과 판정:

| 점검 항목 | 통과 기준 |
|---|---|
| **행위 단위가 명확한가?** | "무엇을 / 어디에 / 어떻게" 가 한 줄로 표현 가능 |
| **영향 범위가 명확한가?** | 변경되는 파일·스킬·정책·사용자 행동이 열거 가능 |
| **검증 방법이 명확한가?** | "어떻게 성공인지" 가 자가 점검·사용 흐름으로 표현 가능 |

- 3개 다 ✓ + 사용자 합의 → **Phase 2 진입** (Seed 박제)
- 3개 중 ❌ 있음 → **다음 라운드 진행**

### Phase 2 — Seed (결정문 박제)

종료 조건 도달 시 `artifacts/interviews/<YYYY-MM-DD>-<slug>.md` 생성. **immutable** (재인터뷰는 새 파일로 진화).

### 종료 조건 (OR — 셋 중 하나 만족 시)

| # | 조건 | 결과 |
|---|---|---|
| a | 사용자가 "충분" 신호 | status: `decided` |
| b | 자가 점검 3개 ✓ + 사용자 합의 | status: `decided` |
| c | 10 라운드 도달 (하드 캡) | status: `dormant` |

## 산출물

```
artifacts/interviews/<YYYY-MM-DD>-<slug>.md
```

포맷:

```markdown
---
date: 2026-06-04
slug: fetcher-automation
status: decided | dormant
source: <회고 거리 출처 등, optional>
---

## 라운드 트레일

R0: 의도 / 옵션 / 선택
R1: ...

## 결정

1~3줄

## 남은 모름 (회고 후보)

- ...
```

## 폴백·재시도

| 트리거 | 대응 |
|---|---|
| 사용자가 도중 다른 주제로 분기 | "지금 인터뷰는 X. 분기하실 거면 중단·이어가기 중 선택" |
| 옵션 비용을 모름 | 작은 정찰 (Bash·WebFetch 등) 후 라운드 재개 |
| 자가 점검 통과 안 됨 | "어느 점검 ❌ 인지" 명시 후 다음 라운드 진행 |
| 10 라운드 도달 | "현재까지 가설" 박제 + status: `dormant`. 다음 인터뷰로 진화 가능 |
| 사용자 중간 종료 | 현재 라운드까지 박제 + status: `dormant` |

## 활동 로그 (자동 기록)

`artifacts/interviews/activity.jsonl` 별도 파일 (행사별 로그와 분리)

```
{"ts": "<ISO 8601>", "skill": "interview", "action": "started" | "decision_reached" | "dormant",
 "details": {"slug": "<인터뷰 슬러그>", "rounds": N, "source": "<회고 거리 출처>"}}
```

기록 실패는 메인 흐름을 막지 않는다 (로그는 보조 정보).

## 자연 호출 후보

| 신호 | 예시 | 적합 |
|---|---|---|
| 의도 자체가 막연 | "이거 어떻게 할까", "별로일까", "보완하고 싶어" | ★★★★★ |
| 정책 결정 미루어짐 | `PROJECT.md` 회고 박스의 `[ ]` 항목 | ★★★★ |
| 새 스킬·기능 추가 검토 | "X 스킬 만들고 싶은데" | ★★★★ |
| 단순 정보 조회 / 명확한 작업 | "S116 마킹해줘" | ❌ — `/session-mark` 직접 호출 |

## 절대 하지 않을 것

- ❌ **인터뷰 도중 다른 스킬 자동 호출** — 결정 → 실행은 별개 흐름. 결정 안 났는데 실행하면 인터뷰 의미 상실
- ❌ **옵션 카탈로그 없이 라운드 진행** — 최소 2개 옵션 + 각 옵션의 트레이드오프 필수
- ❌ **사용자 답 추측해서 라운드 건너뛰기** — "이 사람은 분명 A를 원할 거야" 같은 추측 금지
- ❌ **AI 의견을 첫 옵션에 박기** (선호 유도) — 옵션은 객관 중립. 추천은 사용자 명시 요청 시만
- ❌ **수치 게이트 임의 도입** (점수·임계값) — 본 OS 는 사용자 합의 + 자가 점검 게이트
- ❌ **자가 점검 우회** — 통과 안 됐는데 종료 조건 (b) 발동 금지. (a) 또는 (c) 만 가능
- ❌ **Seed 박제 없이 종료** — 결정 못 났어도 "가설" 로 박제. 흐지부지 방지
- ❌ **외부 OS·도구 비교로 옵션 정당화** — 본 OS 페인포인트로 평가 (메모리 원칙)
