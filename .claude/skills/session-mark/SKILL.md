# session-mark

세션 분류 상태 변경 스킬. 단일 책임: **행사 README 의 한 세션 행 상태 + 진척 카운트를 동시 갱신**.

## 입력

- 행사 슬러그
- 세션 식별자 (세션 슬러그 또는 제목 일부)
- 새 상태: `들음` / `관심` / `스킵` / `미정`

호출 예시:
```
/session-mark aws-summit-seoul-2026 bedrock-deep-dive 관심
```

## 처리 흐름

1. `artifacts/conferences/<행사>/README.md` 읽기
2. 세션 식별자로 해당 행 찾기 (정확 매칭 → 부분 매칭 순)
3. 그 행의 상태 컬럼을 새 상태로 갱신
4. README 상단 진척 카운트(들음/관심/미정/스킵) 재계산
5. 파일 저장

## 폴백·실패 처리

| 트리거 | 대응 |
|---|---|
| 행사 폴더 없음 | "그 행사가 아직 등록되지 않았어요. `/conference-import` 먼저 실행하세요" 안내 |
| 세션 못 찾음 | 비슷한 세션 후보 1~3개 제시해서 사용자 확인 요청 |
| 잘못된 상태 값 | 허용 값 (들음/관심/미정/스킵) 안내 |
| 세션 여러 개 매칭 | 후보 전체 제시해서 명확화 요청 |

## 산출물

`artifacts/conferences/<행사>/README.md` 갱신 (해당 행 상태 + 상단 카운트)

## 활동 로그 (자동 기록)

마킹이 완료되면 활동 로그에 한 줄 append:

```
파일: artifacts/conferences/<행사>/activity.jsonl
포맷:
{"ts": "<ISO 8601>", "skill": "session-mark", "action": "mark",
 "details": {"slug": "<행사 슬러그>", "session": "<세션 슬러그>",
             "from": "<이전 상태>", "to": "<새 상태>"}}
```

기록 실패는 메인 흐름을 막지 않는다 (로그는 보조 정보).

## 절대 하지 않을 것

- ❌ **세션 노트 파일 건드리기** — 이 스킬은 README 의 한 행만. `sessions/<slug>.md` 는 `session-note` 영역
- ❌ **여러 행사·세션 동시 마킹** — 한 번에 한 행사·한 세션
- ❌ **상태 추측** — 사용자가 명시한 상태만. "아마 관심일 듯" 같은 추론 금지
- ❌ **사용자 확인 없이 부분 매칭으로 진행** — 후보 여럿이면 무조건 명확화 요청
