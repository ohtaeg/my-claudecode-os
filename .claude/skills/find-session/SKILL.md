# find-session

세션 제목 키워드 검색 스킬. 단일 책임: **한 행사의 세션 제목에서 키워드(공백 구분 OR 매칭) 매칭된 세션의 ID + 이름 + 상태 + 노트 유무를 표로 출력**.

## 입력

- 행사 슬러그
- 키워드 1개 이상 (공백 구분, OR 매칭, 대소문자 무시)

호출 예시:
```
/find-session aws-summit-seoul-2026 Bedrock
/find-session aws-summit-seoul-2026 Bedrock Kiro Claude
```

## 처리 흐름

1. `artifacts/conferences/<행사>/README.md` 읽기
2. 세션 행에서 **제목** 만 추출 (발표자·트랙은 대상 아님)
3. 각 제목에 대해 키워드 중 **하나라도 포함**되면 매칭 (대소문자 무시)
4. 매칭 수 + 표 출력 (`/conference` 와 같은 형식)
5. 노트 컬럼은 `sessions/<세션>.md` 존재 여부로 결정 (✓ / —)

## 출력 형식

**매칭 있음**:
```
AWS Summit Seoul 2026 — "Bedrock | Kiro" 매칭 9 세션

| ID  | 상태 | 세션 이름 | 노트 |
|-----|---|---|---|
| S41 | 관심 | 캐치테이블의 ClaudeCode on Bedrock Proxy를 통한 AI 운영 전략 | — |
| S7  | 미정 | Kiro CLI로 실현한 여기어때의 데이터베이스 현대화 | — |
| S99 | 미정 | ... | — |
```

ID 는 `/session-mark` / `/session-preview` 호출 시 그대로 사용 (예: `/session-mark <행사> S41 관심`).

**매칭 0**:
```
AWS Summit Seoul 2026 — "xxx" 매칭 0 세션
```

## 폴백·실패 처리

| 트리거 | 대응 |
|---|---|
| 행사 폴더 없음 | "그 행사가 아직 등록되지 않았어요. `/conference-import` 먼저 실행하세요" 안내 |
| 키워드 누락 | "키워드가 필요합니다. 호출 예: `/find-session <행사> <키워드>`" 안내 |
| 매칭 0 | 알림만 ("매칭 0 세션") — **유사어 제안 없음** |
| 1글자 키워드 | 경고 + 그래도 출력 ("키워드가 너무 짧아 매칭이 광범위할 수 있어요") |
| README 세션 테이블 손상 | 손상된 행은 건너뛰고 매칭 결과만 출력 |

## 절대 하지 않을 것

- ❌ **세션 내용·인사이트 출력** — ID·이름·상태만. 내용 미리보기는 `/session-preview` 영역
- ❌ **상태 변경** — 읽기 전용
- ❌ **전체 행사 횡단 검색** — 한 행사만. 여러 행사 인덱스 조회는 OS 가 의도적으로 만들지 않는 영역
- ❌ **키워드 동의어·자동 확장** — 사용자 명시 키워드만 그대로 매칭. "AI" 요청에 "ML" 자동 포함 같은 추론 금지
- ❌ **발표자·트랙 등 다른 컬럼 검색** — 제목만. 범위 확장은 자라날 단계 후보
- ❌ **결과 임의 압축·정렬 변경** — `/conference` 와 같은 단순 상태 그룹 순서 (관심 → 미정 → 들음 → 스킵). "관련도 점수" 같은 자체 점수 부여 금지
