# Tech Q&A Skill

클로드 코드 / 개발 관련 질문에 **일관된 형식**으로 답변하기 위한 가이드.
일반 대화에서는 호출되지 않으며, 사용자가 `/tech-qna ...` 로 명시적으로 부를 때만 동작한다.

## 0. 사전 확인 (Pre-flight)

답변을 시작하기 전에 다음을 **순서대로** 수행한다.

1. **주제 분류**: 질문이 어느 영역인지 식별
   - `claude-code` — Claude Code CLI/IDE 기능 (slash command, hook, MCP, settings 등)
   - `claude-api` — Anthropic SDK / API (tool use, prompt caching, models 등)
   - `dev-general` — 그 외 일반 개발 (언어, 프레임워크, 도구 등)
2. **범위 적절성**: 질문이 너무 광범위하면(예: "리액트 알려줘") 답변 전에 좁혀줄 것을 제안한다
3. **현재 프로젝트 관련성**: 현재 작업 디렉터리(`my-claudecode-os`)와 관련된 질문이면, 코드/설정을 먼저 확인한 뒤 답변한다
4. **출처 사전 확보 (필수)**: 답변을 작성하기 **전에** 출처를 먼저 확정한다.
   - 공식 문서가 필요한 질문이면 **반드시 `WebFetch`를 먼저 호출**해 실제 응답을 받고 본문에 인용할 사실을 그 응답에서 가져온다.
   - 응답이 redirect/404/접근 불가면 다른 URL로 재시도하거나 "내장 지식"으로 명시한다.
   - "이 답변에 출처가 있을까?"가 No이면 작성하지 않고, 모른다고 답하거나 검색한다.

## 1. 답변 형식 (고정 템플릿)

답변은 **항상 다음 4개 섹션**을 이 순서로 가진다. **`📚 출처`는 반드시 답변의 맨 하단**에 위치한다. 빈 섹션은 생략하지 않고 "해당 없음"이라고 적는다.

```markdown
## 🔍 질문 재정리
> 사용자의 질문을 한 문장으로 재정리. 모호하다면 가정을 명시("X로 가정하고 답변").

## 💡 핵심 답변
- 한두 문장으로 결론부터.
- 그 뒤에 필요한 만큼 보강 설명. 코드 예시는 가능한 한 포함.

## ⚠️ 주의점 / 흔한 실수
- 초보자가 자주 빠지는 함정, edge case, 비슷한 개념과의 혼동 포인트.
- 없으면 "해당 없음".

## 📚 출처
- 공식 문서 URL (있으면 반드시 포함, **`WebFetch`로 실제 조회한 것만** 기재)
- 프로젝트 코드 인용 시 `파일경로:라인` 형식
- 클로드 내장 지식만 사용한 경우 → "Claude 내장 지식 — 최신 사양과 다를 수 있음" 명시
- 출처가 둘 이상이면 **신뢰도 높은 것부터** 위에서 아래로 나열
```

### 좋은 예 / 나쁜 예

| 좋은 예                                              | 나쁜 예                                          |
| ---------------------------------------------------- | ------------------------------------------------ |
| 질문 재정리에 "macOS 기준으로 가정" 같이 가정 명시   | 모호한 질문을 그대로 두고 답변                   |
| 핵심 답변 첫 줄이 결론                               | 배경 설명부터 시작해서 결론이 뒤에 묻힘          |
| 출처에 docs.claude.com 링크 포함                     | 출처 섹션을 통째로 생략                          |

## 2. 출처 처리 규칙

**공식 문서 우선** — 클로드 코드 / API 관련은 가능하면 `WebFetch`로 다음 도메인을 직접 조회해 최신 정보를 확인한다.

| 영역         | 우선 도메인                                  |
| ------------ | -------------------------------------------- |
| claude-code  | `docs.claude.com/en/docs/claude-code/...`    |
| claude-api   | `docs.claude.com/en/api/...`, `docs.claude.com/en/docs/...` |
| dev-general  | 해당 언어/프레임워크 공식 문서 (MDN, React docs, Python docs 등) |

### 출처 결정 순서

1. **현재 프로젝트 코드/설정**이 답을 가지고 있는가? → 그것이 1차 출처. 파일 경로:line 형식으로 표기.
2. **공식 문서**에 답이 있는가? → `WebFetch`로 조회 후 URL을 출처에 명시.
3. **둘 다 아니면** 내장 지식으로 답변하되, 출처 섹션에 "Claude 내장 지식 — 최신 사양과 다를 수 있음" 경고를 명시.

### 출처 검증 절차 (Verify before cite)

출처 섹션에 URL을 적기 전에 **반드시** 다음을 만족시킨다.

- ✅ 이 세션에서 **실제로 `WebFetch`로 응답을 받은** URL인가? (응답 본문이 답변의 사실 근거인가)
- ✅ redirect가 있었다면 **최종 URL**을 기재했는가?
- ✅ 404 / 접근 차단 / 빈 응답이었다면 그 URL은 **삭제**했는가?
- ❌ "있을 법한" URL은 절대 적지 않는다 — 도메인 패턴만 보고 추측해 만든 URL은 거짓 출처다.

검증을 통과한 URL이 하나도 없으면, 출처 섹션에 URL을 적지 않고 "Claude 내장 지식"으로 명시한다.

### WebFetch 사용 기준

- 클로드 코드 / API의 **구체적인 옵션, 파라미터, 모델명, 버전별 차이** 질문 → 거의 항상 WebFetch
- 일반 개념 설명 ("hook이 뭐야?" 수준) → 내장 지식만으로 충분할 수 있으나, 자신 없으면 WebFetch
- 답을 모르면 **추측하지 말고** 검색하거나 모른다고 답변한다

## 3. 답변 분량 가이드

- **개념 질문** ("X가 뭐야?"): 핵심 답변 3-5줄 + 짧은 예시 1개
- **방법 질문** ("어떻게 X해?"): 단계별 절차 + 실행 가능한 코드/명령어
- **비교 질문** ("X와 Y 차이는?"): 표 형식 권장
- **에러/디버깅 질문**: 원인 → 확인 방법 → 해결책 순서

길이 < 정확성. 모르면 모른다고 답하는 게 길게 추측하는 것보다 낫다.

## 4. 사용 예시

### 입력
```
/tech-qna Claude Code의 hook이랑 slash command 차이가 뭐야?
```

### 출력 골격
```markdown
## 🔍 질문 재정리
> Claude Code에서 hook과 slash command의 역할/실행 시점 차이를 묻는 질문으로 이해.

## 💡 핵심 답변
- **slash command**: 사용자가 명시적으로 `/cmd` 입력 시 실행되는, Claude가 호출하는 동작.
- **hook**: 특정 이벤트(예: tool 사용 전/후) 발생 시 settings.json 설정에 따라 **harness가 자동 실행**하는 셸 명령.
- 핵심 차이: 호출 주체(Claude vs harness)와 트리거(명시 vs 이벤트).

(필요 시 settings.json 예시)

## ⚠️ 주의점 / 흔한 실수
- "자동으로 X 해줘" 요청은 memory가 아니라 hook으로 구현해야 한다 — Claude는 자기 자신을 매번 트리거할 수 없음.

## 📚 출처
- https://docs.claude.com/en/docs/claude-code/hooks
- https://docs.claude.com/en/docs/claude-code/slash-commands
```

## 5. 금지 사항 (Never do)

- ❌ **출처 없는 단정** — "X는 Y이다"라고 단정하려면 출처를 댈 수 있어야 한다. 없으면 "내가 알기로는" 같은 표현을 쓴다
- ❌ **URL 추측/생성** — 본 적 없는 docs URL을 만들어내지 않는다. 확실한 것만 적는다
- ❌ **질문 재정리 생략** — 짧은 질문이라도 한 줄짜리 재정리는 반드시 둔다 (의도 확인 = 잘못된 답변 방지)
- ❌ **현재 프로젝트 무시** — `.claude/` 안의 질문이면 먼저 프로젝트 파일을 읽는다. 일반론으로 흘리지 않는다
- ❌ **답변 후 추가 작업** — 이 스킬은 **답변만** 한다. 사용자가 명시적으로 요청하지 않으면 코드 수정/파일 생성을 하지 않는다

## 6. 체크리스트

답변 직전 마음속으로 확인:

- [ ] 질문을 한 줄로 재정리했는가
- [ ] 핵심 답변 첫 줄이 결론인가
- [ ] 공식 문서를 확인해야 하는 질문인데 WebFetch를 건너뛰지 않았는가
- [ ] **출처 섹션이 답변의 맨 하단에 위치하는가**
- [ ] **출처의 모든 URL을 이 세션에서 실제로 WebFetch했는가** (추측 URL 0건)
- [ ] redirect된 URL은 최종 주소로 적었는가
- [ ] 검증된 출처가 없으면 "Claude 내장 지식"으로 정직하게 표기했는가
- [ ] 4개 섹션(재정리/답변/주의점/출처)을 모두 채웠는가
